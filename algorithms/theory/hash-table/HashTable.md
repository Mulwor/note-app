## Hash-table — хеш-таблица

Хеш-таблица (Hash Table) — это структура данных, которая использует хеш-функцию для быстрого хранения и поиска данных по ключу или значению.

В основе хеш-таблицы лежит хеш-функция, которая преобразует ключ в число — хеш. По этому хешу определяется место, где будет храниться значение.

<a id="hash-table-map"></a>

В JavaScript для хранения данных в формате ключ → значение можно использовать Map и Object.

```js
const users = new Map();

// ? Добавление: map.set(key, value) — O(1) в среднем.
users.set('user1', 'John');
users.set('user2', 'Alice');

// Получение map.get(key) — O(1) в среднем.
console.log(users.get('user1')); 
// Удаление: map.delete(key) — O(1) в среднем.
console.log(users.delete('user1'))
// Проверка наличия: map.has(key) — O(1) в среднем.
console.log(users.has('user2')); 
```

Например есть ключ: "user123" → hash → 42

После этого хеш-таблица использует полученное значение, чтобы быстро определить, где находится нужный элемент. Иногда разные ключи могут получить одинаковый хеш. Это называется коллизией. Хеш-таблица должна уметь обрабатывать такие ситуации, например хранить несколько элементов в одной ячейке.

Где применяются хеш-таблицы?

- Быстрый поиск данных по ключу.
- Хранение пар ключ → значение.
- Кэширование данных.
- Подсчёт количества повторений элементов.
- Проверка, встречался ли элемент раньше.
- Реализация Set, Map и других структур данных.
- Хранение данных пользователей по id.

Главная идея: хеш-таблица использует ключ и хеш-функцию, чтобы находить нужное значение очень быстро — обычно за O(1). 

<a id="hash-table-set"></a>

`Set` — это структура данных, которая хранит только уникальные значения и позволяет быстро добавлять, удалять и проверять наличие элемента. В отличие от Map, `Set` не хранит пары ключ → значение. Каждый элемент сам является значением.

```js
const users = new Set();

// Добавление: set.add(value) — O(1) в среднем.
users.add('John');
users.add('Alice');
users.add('John'); // повторно не добавится

// Проверка наличия: set.has(value) — O(1) в среднем.
console.log(users.has('John')); // true

// Удаление: set.delete(value) — O(1) в среднем.
console.log(users.delete('John')); // true
console.log(users.has('John')); // false

// в результате: Set { 'Alice' }

```

В основе Set во многих реализациях используется хеширование, благодаря чему можно быстро проверить, существует ли значение. Например, есть значение: "Alice" → hash → 42. После этого хеш-таблица использует полученное значение, чтобы быстро определить, где находится элемент. Если два разных значения получают одинаковый хеш, возникает коллизия. Реализация Set должна уметь обрабатывать такие ситуации.

Где применяется Set?
- Хранение только уникальных значений.
- Удаление дубликатов из массива.
- Быстрая проверка, встречался ли элемент раньше.
- Хранение уникальных id.
- Проверка наличия пользователя, товара или другого объекта.
- Поиск пересечений и различий между наборами данных.

```js
const numbers = [1, 2, 2, 3, 3, 4];
return [...new Set(numbers)];
```

Главная идея: Set хранит только уникальные значения и благодаря хешированию позволяет быстро добавлять, удалять и проверять наличие элементов — обычно за O(1) в среднем.

<a id="hash-table-set-dif_1"></a>

Map используется для `хранения` и быстрого поиска `значений по ключу`, а Set — для `хранения уникальных значений` и быстрой проверки их наличия.


<a id="hash-table-weak"></a>

`WeakMap и WeakSet` — это специальные структуры данных, похожие на Map и Set, но с особым поведением при работе со сборщиком мусора (Garbage Collector). Главная особенность — они не препятствуют удалению объектов из памяти, если на эти объекты больше нет других ссылок.

`WeakMap` - хранит пары объект → значение. В отличие от обычного Map, ключами WeakMap `могут быть только ОБЪЕКТЫ`. WeakMap содержит основные методы Map: set(), get(), has() и delete(). 

Почему WeakMap называется Weak?

```js
const cache = new WeakMap();
let user = { name: 'John' };
cache.set(user, 'some data');
user = null;
```

У обычного Map объект продолжал бы удерживаться в памяти: Map → object ← Map продолжает хранить ссылку. А у WeakMap: WeakMap → object ← может быть удалён Garbage Collector

WeakSet похож на Set, но может хранить только объекты. WeakSet содержит основные методы Set: add(), has() и delete(). WeakSet хранит уникальные объекты. Уникальность определяется по ссылке на объект, а не по его содержимому. 

```js
const a = { name: 'John' };
const b = { name: 'John' };

const set = new WeakSet();

set.add(a);
set.add(b);

console.log(set.has(a)); // true
console.log(set.has(b)); // true
```

Здесь a и b считаются разными объектами.  А если добавить один и тот же объект дважды:

```js
const a = { name: 'John' };

const set = new WeakSet();

set.add(a);
set.add(a);
```

В WeakSet нельзя добавлять примитивы:

```js
const users = new WeakSet();
users.add({ name: 'John' }); // ✅

// users.add('John'); // ❌ ошибка
// users.add(10);     // ❌ ошибка
```

Когда использовать?
- WeakMap → когда нужно хранить дополнительные данные, связанные с объектом, но не мешать этому объекту удаляться из памяти. object → дополнительные данные
- WeakSet → когда нужно просто отслеживать набор объектов, не мешая Garbage Collector удалять их. 

Главная идея WeakMap и WeakSet: они предназначены в первую очередь для работы с объектами, которые могут быть автоматически удалены из памяти Garbage Collector, когда на них больше нет других сильных ссылок.
