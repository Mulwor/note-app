## Big o notation - сложность алгоритма

Big O Notation - используется для описания (оценки) сложности алгоритма. Он показывает как будет меняться производительность алгоритма, в зависимости от роста входящих данных. При увеличении входящих данных будет расти две вещи - время (за которое будет отрабатывать наш алгоритм) и кол-во памяти используемых для обработки этих данных.

Данная концепция:

- позволяет описывать скорость роста функции в зависимости от размера входных данных;
- может быть использована для оценки эффективности алгоритма по отношению к использованию как времени (временная сложность) так и памяти (пространственная сложность);
- полезна при сравнении различных алгоритмов и их потенциальной производительности при увеличении размера входных данных;

При разработке алгоритмов важно учитывать их о-нотацию:

- позволяет получить представление о том, как алгоритмы будут вести себя при больших объемах данных.
- позволяет нам работать с приближенными математическими выражениями, опуская меньшие слагаемые. Именно это причина позволяет нам не указывать основания по тому или иному критерию

## Array (массив) в JavaScript

**Массив** — это упорядоченная коллекция значений, которая может содержать элементы любых типов (числа, строки, объекты, функции и даже другие массивы). В JavaScript массивы являются **динамическими** — их размер может меняться во время выполнения программы.

```js
const arr = [1, 'two', { name: 'John' }];
console.log(arr.length); // 3
arr.push(4);             // добавляем элемент — длина становится 4
```

Динамические массивы - это структура данных, которая автоматически управляет памятью при добавлении или удалении элементов. В JavaScript все массивы динамические.

Основные операции:
- Добавление в конец: arr.push(value) — O(1) в среднем.
- Удаление с конца: arr.pop() — O(1).
- Добавление в начало: arr.unshift(value) — O(n), т.к. все элементы сдвигаются.
- Удаление из начала: arr.shift() — O(n).
- Доступ по индексу: arr[index] — O(1).
- Поиск элемента: arr.indexOf(value) — O(n).

```js
const numbers = [10, 20, 30];
numbers.push(40);        // [10, 20, 30, 40]
numbers.pop();           // [10, 20, 30]
numbers.unshift(5);      // [5, 10, 20, 30] – все сдвинулись
console.log(numbers[1]); // 10
```

Где применяются массивы?
- Хранение списков (пользователи, товары, сообщения).
- Очереди и стеки (с помощью push/pop или unshift/shift).
- Обработка данных (фильтрация, сортировка, преобразование).
- Реализация других структур (например, стек на основе массива).

## Hash-table — хеш-таблица

Хеш-таблица (Hash Table) — это структура данных, которая использует хеш-функцию для быстрого хранения и поиска данных по ключу или значению.

В основе хеш-таблицы лежит хеш-функция, которая преобразует ключ в число — хеш. По этому хешу определяется место, где будет храниться значение.

<a id="hash-table-map"></a>

В JavaScript для хранения данных в формате ключ → значение можно использовать Map и Object.

```js
const users = new Map();

// ? Добавление: map.set(key, value) — O(1) в среднем.
users.set('user1', 'John');
users.set('user2', 'Alice');

// Получение map.get(key) — O(1) в среднем.
console.log(users.get('user1')); 
// Удаление: map.delete(key) — O(1) в среднем.
console.log(users.delete('user1'))
// Проверка наличия: map.has(key) — O(1) в среднем.
console.log(users.has('user2')); 
```

Например есть ключ: "user123" → hash → 42

После этого хеш-таблица использует полученное значение, чтобы быстро определить, где находится нужный элемент. Иногда разные ключи могут получить одинаковый хеш. Это называется коллизией. Хеш-таблица должна уметь обрабатывать такие ситуации, например хранить несколько элементов в одной ячейке.

Где применяются хеш-таблицы?

- Быстрый поиск данных по ключу.
- Хранение пар ключ → значение.
- Кэширование данных.
- Подсчёт количества повторений элементов.
- Проверка, встречался ли элемент раньше.
- Реализация Set, Map и других структур данных.
- Хранение данных пользователей по id.

Главная идея: хеш-таблица использует ключ и хеш-функцию, чтобы находить нужное значение очень быстро — обычно за O(1). 

<a id="hash-table-set"></a>

`Set` — это структура данных, которая хранит только уникальные значения и позволяет быстро добавлять, удалять и проверять наличие элемента. В отличие от Map, `Set` не хранит пары ключ → значение. Каждый элемент сам является значением.

```js
const users = new Set();

// Добавление: set.add(value) — O(1) в среднем.
users.add('John');
users.add('Alice');
users.add('John'); // повторно не добавится

// Проверка наличия: set.has(value) — O(1) в среднем.
console.log(users.has('John')); // true

// Удаление: set.delete(value) — O(1) в среднем.
console.log(users.delete('John')); // true
console.log(users.has('John')); // false

// в результате: Set { 'Alice' }

```

В основе Set во многих реализациях используется хеширование, благодаря чему можно быстро проверить, существует ли значение. Например, есть значение: "Alice" → hash → 42. После этого хеш-таблица использует полученное значение, чтобы быстро определить, где находится элемент. Если два разных значения получают одинаковый хеш, возникает коллизия. Реализация Set должна уметь обрабатывать такие ситуации.

Где применяется Set?
- Хранение только уникальных значений.
- Удаление дубликатов из массива.
- Быстрая проверка, встречался ли элемент раньше.
- Хранение уникальных id.
- Проверка наличия пользователя, товара или другого объекта.
- Поиск пересечений и различий между наборами данных.

```js
const numbers = [1, 2, 2, 3, 3, 4];
return [...new Set(numbers)];
```

Главная идея: Set хранит только уникальные значения и благодаря хешированию позволяет быстро добавлять, удалять и проверять наличие элементов — обычно за O(1) в среднем.

<a id="hash-table-set-dif_1"></a>

Map используется для `хранения` и быстрого поиска `значений по ключу`, а Set — для `хранения уникальных значений` и быстрой проверки их наличия.


<a id="hash-table-weak"></a>

`WeakMap и WeakSet` — это специальные структуры данных, похожие на Map и Set, но с особым поведением при работе со сборщиком мусора (Garbage Collector). Главная особенность — они не препятствуют удалению объектов из памяти, если на эти объекты больше нет других ссылок.

`WeakMap` - хранит пары объект → значение. В отличие от обычного Map, ключами WeakMap `могут быть только ОБЪЕКТЫ`. WeakMap содержит основные методы Map: set(), get(), has() и delete(). 

Почему WeakMap называется Weak?

```js
const cache = new WeakMap();
let user = { name: 'John' };
cache.set(user, 'some data');
user = null;
```

У обычного Map объект продолжал бы удерживаться в памяти: Map → object ← Map продолжает хранить ссылку. А у WeakMap: WeakMap → object ← может быть удалён Garbage Collector

WeakSet похож на Set, но может хранить только объекты. WeakSet содержит основные методы Set: add(), has() и delete(). WeakSet хранит уникальные объекты. Уникальность определяется по ссылке на объект, а не по его содержимому. 

```js
const a = { name: 'John' };
const b = { name: 'John' };

const set = new WeakSet();

set.add(a);
set.add(b);

console.log(set.has(a)); // true
console.log(set.has(b)); // true
```

Здесь a и b считаются разными объектами.  А если добавить один и тот же объект дважды:

```js
const a = { name: 'John' };

const set = new WeakSet();

set.add(a);
set.add(a);
```

В WeakSet нельзя добавлять примитивы:

```js
const users = new WeakSet();
users.add({ name: 'John' }); // ✅

// users.add('John'); // ❌ ошибка
// users.add(10);     // ❌ ошибка
```

Когда использовать?
- WeakMap → когда нужно хранить дополнительные данные, связанные с объектом, но не мешать этому объекту удаляться из памяти. object → дополнительные данные
- WeakSet → когда нужно просто отслеживать набор объектов, не мешая Garbage Collector удалять их. 

Главная идея WeakMap и WeakSet: они предназначены в первую очередь для работы с объектами, которые могут быть автоматически удалены из памяти Garbage Collector, когда на них больше нет других сильных ссылок.

<summary>Stack and queue - стек и очередь </summary>

Стек (stack) — структура данных, которая работает по принципу «последним пришёл, первым ушёл» (LIFO — last in, first out). Стек можно представить как некий контейнер, в котором элементы (например, числа, символы и так далее) могут быть добавлены в вершину, а затем извлечены только из вершины. В бытовом плане стек напоминает стопку тарелок. Тогда тарелка, которую положили первой, в самый низ, будет использована последней.

Существуют различные реализации стека. Например, стек может быть реализован на массиве, на односвязном списке, на двусвязном списке и так далее. Основные операции, которые можно производить со стеком, включают:

✅ Добавление элемента в вершину стека (push) - O(1)
✅ Удаление элемента из вершины стека (pop) - O(1)
✅ Возврат верхнего элемента без его удаления (peek) - O(1)
✅ Проверка стека на пустоту (isEmpty) - O(1)

Стоит отметить, что стек представляет собой список с элементами и указателя на вершину стека, указывающего на последний элемент, добавленный в стек.

Каждый раз, когда в стек добавляется новый элемент, указатель на вершину смещается на следующий элемент. Когда элемент удаляется из вершины стека, указатель смещается на предыдущий элемент. Если указатель находится в конце стека, то стек пуст.

---

Очереди очень похожи на стеки. Они также не дают доступа к произвольному элементу. Очередь работает по принципу «первый вошел, первый вышел» (First-In-First-Out или FIFO). То есть забирать элементы из очереди мы будем в том же порядке, что и клали. Как реальная очередь или конвейер.

Очереди часто используются в программах для реализации буфера, в который можно положить элемент для последующей обработки, сохраняя порядок поступления. Например, если база данных поддерживает только одно соединение, можно использовать очередь потоков, которые будут, как ни странно, ждать своей очереди на доступ к БД.

</details>

необходимую нам информацию в больших объемах `отсортированных` данных. Например нам нужно найти

Бинарный поиск имеет следующие сложности:

- Логарифмическая временная сложность — O(logN).
- Постоянная пространственная сложность по памяти — O(1).

выкидываем. Затем с правой части мы делаем все тоже самое мы делим ее на два и отбрасываем ту которая не подходит

<summary>Linked list - связанный список</summary>

Односвязный список - структура данных, в которых элементы хранятся линейно. Каждый элемент помимо того, что в себе хранит какие-то данные, он еще содержит ссылку на следующий элемент.

Стоит уточнить, что последний элемент ссылки равно null. У списка есть два свойства - Head (ссылка на самый первый элемент списка), Tail (ссылка на самый последний элемент списка)

Двусвязный список - отличается от односвязного списка тем, что он содержит ссылку на предыдущий элемент и на следующий элемент.

Различие между списком и массивом

1. У списка нельзя найти элемент по индексу, в то время как у массива можно
2. Содержит ссылку на следующий элемент, в то время как у массива нет информа-
ции о следующем элементе

<summary>Trees</summary>

Trees - структура данных, которая состоит из узлов, связывающая между собой
в виде древовидной структуры. Состоит бинарное дерево из:

- root - начальный узел дерева, от которого исходят остальные узлы;
- parent - узел, который имеет дочерние узлы;
- child - узел, напрямую соединяенный с другим узлом при удалении от корня;
- leaf - узел, который не имеет детей
- siblings - группа узлов с одним родителям
- edge - направления
