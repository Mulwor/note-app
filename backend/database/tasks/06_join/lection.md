JOIN - объединения таблиц. Например: у нас есть 2 таблицы: 

Left
| order_id | user_id |
| :--- | :--- |
| 592 | 500 |
| 593 | 501 |

Right
| order_id | courier_id |
| :--- | :--- |
| 592 | 148 |
| 594 | 57 |

Напомним, что в user_actions - это информация о том, что различные пользователи делают с товарами, table_actions - это что делают курьеры. И мы хотим с джойнить это так, чтобы у нас была информация про каждый заказ и еще колонки user_id, order_id

```sql
SELECT * FROM t1
LEFT JOIN t2 
ON t1.order_id = t2.order_id
```

| order_id | user_id | order_id1 | courier_id
| :--- | :--- | :--- | :--- |
| 592 | 500 | 592 | 148 | 
| 593 | 501 | ... | ... |

`LEFT JOIN` - в начале берем левую таблицу с id и идем в правую таблицу и смотрим совпадает ли условие равенство id - 592 (оба id слева и справа одинакова), джойнили их и мы видим, что слева курьер с id 148 добавился. А что касается второго, то так как айдишки не совпали (слева и справа), то он просто вывел левые значение с id с пустыми значениями

`RIGHT JOIN` - работает по такому же принципу только теперь берется правая часть и сравнивается слевой. Если находит, то джойнит эти значения, если нет возвращает только правое значение

```sql
SELECT * FROM t1
RIGHT JOIN t2 
ON t1.order_id = t2.order_id
```

| order_id | user_id | order_id1 | courier_id
| :--- | :--- | :--- | :--- |
| 592 | 500 | 592 | 148 | 
| ... | ... | 594 | 57 |

`INNER JOIN` - он берет за основу левую и правую таблицу и данные которые у нас совпадает слева и справа он выводит

```sql
SELECT * FROM t1
INNER JOIN t2 
ON t1.order_id = t2.order_id
```

| order_id | user_id | order_id1 | courier_id
| :--- | :--- | :--- | :--- |
| 592 | 500 | 592 | 148 | 

`FULL (OUTER) JOIN` - он берет и выводит все значения как в левой таблице, так и в правой. Там где мы смогли объединить - объединил, там где нет - вывели значения 

```sql
SELECT * FROM t1
FULL JOIN t2 
ON t1.order_id = t2.order_id
```

| order_id | user_id | order_id1 | courier_id
| :--- | :--- | :--- | :--- |
| 592 | 500 | 592 | 148 | 
| 593 | 501 | ... | ... |
| ... | ... | 594 | 57 |

Например - мы хотим посмотреть сколько у нас было создано заказов в разбивке по возрастным группам наших пользователей

```sql
SELECT COUNT(order_id)
FROM (
  SELECT DISTINCT user_action.user_id, order_id, birth_date
  FROM user_actions
  LEFT JOIN users
  ON user_actions.user_id = users.user_id
) t1
```

Если имя поля, по которому происходит объединение, совпадает в обеих таблицах (как в примерах выше), то можно использовать сокращенную запись c оператором USING:

```sql
SELECT a.column_1, b.column_2
FROM table_1 a 
  JOIN table_2 b
  USING (id)
```

Процесс объединения можно представить в виде следующей последовательности операций:

1. Сначала каждая строка первой таблицы сопоставляется с каждой строкой второй таблицы. т.е. происходит декартово произведение двух множеств, результатом которого является новое множество, состоящее из всевозможных пар исходных строк. Например, если в одной таблице было 50 записей, а в другой 10, то в результате декартова произведения получится 500 записей. На игрушечном примере это можно представить следующим образом:

2. Затем для каждой объединённой строки, состоящей из строк двух исходных таблиц, проверяется условие соединения, указанное после оператора ON.

3. После этого в соответствии с выбранным типом объединения формируется результирующая таблица. 

При соединении не двух, а нескольких таблиц, операция соединения выполняется последовательно несколько раз, т.е. описанный выше алгоритм запускается столько раз, сколько указано соединений. При этом в этой последовательности при каждом объединении может использоваться любой тип соединения (INNER, LEFT и т.д.).

Для двух соединений запрос может выглядеть примерно следующим образом:
```sql
SELECT a.column_1, b.column_2
FROM table_1 a 
     LEFT JOIN table_2 b
     ON a.user_id = b.user_id
     JOIN table_3 c
     ON b.order_id = c.order_id
...
```
