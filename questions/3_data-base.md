1. Что такое индексы. Какие есть плюсы (преимущество) и минусы (недостатки) у него?

Это отдельная структура данных, которая лежит рядом с таблицей данных (база-данных) позволяет ускорять чтения, но замедляет запись и изменения каких-либо данных. Иными словами она позволяет индексировать и находить какие-то куски памяти то есть какие-то конкретные записи условно как закладка книги,  показывает где какая запись лежит.

Из недостатков: 
- Любое изменения/удаления/обновления данных, которые проиндексированы оно будет медленное. Помимо самой этой операции нужно еще обновить индекс

2. Какие виды индексов существует в postgreSQL и зачем они нужны?

Самый популярный B-tree - это сбалансированное дерево, которая поддерживает операции - равно, больше, меньше, like, between. У него алгоритмическая  сложность log(N)

Есть еще Hash index - он работает по строгому равенству, и он будет быстрее у него алгорт.сложность O(1) - тобишь буквально находит по хешу

GIN - поиск по тексту записи, он берет буквально каждое слово и запоминает (хранит) у себя в каких строчках оно находится. Например у нас есть слово python и он хранит у себя это слово и говорит в каких индексах это находится. 

```sql
python -> [11, 37, 80]
backend -> [5, 37, 64]
```

И когда мы пишем слово python он как раз и отдает эти 3 строчки

```sql
SELECT * FROM vacancies
WHERE to_tsvector(text) @@ to_tsquery('python')
```

Есть еще GIST - для работы с геоданными - IP, геолокация, расстояние. SP-GIST делит на зоны, чтобы было удобнее искать работа с геоданными. BRIN менее точный, зато очень легкий. Например есть огромная таблица и потребность чтобы индекс занимал минимум места - прикидывает конкретный диапазон значений. Может потерять какую-то точность, но весит меньше
