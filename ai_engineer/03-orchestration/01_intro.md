Данный модуль посвящен AI-оркестрации - а именно как использовать искусственный интеллект для управления и автоматизации рабочих процессов (workflow). Вместо того чтобы вручную писать сложный код и конфигурации, вы описываете задачу на естественном языке, а AI помогает построить и выполнить её.

🎯 Зачем это нужно?

Традиционные AI-ассистенты (как ChatGPT) не знают ваш код, ваши данные и актуальную документацию. Они дают общие ответы, которые могут быть неточными. Этот модуль учит контекстной инженерии — как правильно предоставить AI нужный контекст, чтобы он работал надёжно и точно.

🔧 Три ключевых инструмента

Модуль знакомит с тремя техниками, которые реализуются через платформу Kestra:

- `AI Copilot` — это помощник, который генерирует код workflow (на YAML) по вашему текстовому описанию. Вы объясняете, что хотите сделать, а Copilot создаёт структуру потока, избавляя от рутинного написания кода.

- `RAG (Retrieval Augmented Generation)` — техника, которая позволяет AI отвечать на вопросы, опираясь на реальные данные из ваших источников. Сначала система находит нужную информацию (например, в документации), затем добавляет её в запрос к модели, и только после этого генерирует ответ. Это drastically снижает риск «галлюцинаций».

- `AI-агенты` — это автономные системы, которые могут сами принимать решения и использовать инструменты для выполнения сложных задач. В Kestra есть готовый плагин AIAgent, который управляет логикой агента.

🧪 Эксперимент, который всё объясняет

Например - если открыть ChatGPT в приватном окне и попросить его создать Kestra flow для загрузки данных о такси Нью-Йорка из CSV в BigQuery, результат, скорее всего, будет содержать ошибки.

ChatGPT сгенерирует YAML-код, который выглядит правдоподобно, но на практике содержит:

- Устаревший синтаксис плагинов (например, старые типы задач, которые уже переименованы).
- Некорректные имена свойств (свойства, которых нет в текущих версиях).
- Выдуманные возможности (задачи, триггеры или свойства, которых никогда не существовало).

❓ Почему так происходит?

Причина в том, что большие языковые модели (LLM) обучаются на данных за определённый период времени. Они не знают о:

- Обновлениях программного обеспечения и новых релизах.
- Переименованных плагинах или изменённых API.
- Новых лучших практиках в вашей организации.
- Специфических конфигурациях вашей инфраструктуры.

Это фундаментальная проблема: модель может работать только с той информацией, к которой у неё есть доступ. Без правильного контекста универсальные AI-ассистенты «галлюцинируют», создавая устаревший или неверный код, которому нельзя доверять в production.

💡 Что такое контекстная инженерия?

Контекстная инженерия — это дисциплина о том, как предоставить модели именно ту информацию, которая нужна ей в нужный момент. Это не просто написание хорошего промпта, а построение целой системы, которая автоматически извлекает, фильтрует, форматирует и внедряет нужные данные в контекстное окно модели перед генерацией ответа.

Это важное смещение фокуса:

- Промпт-инженерия — это написание вопроса.
- Контекстная инженерия — это построение системы, которая предоставляет ответ.

С правильным контекстом AI генерирует точный, актуальный, готовый к production код, который можно быстро дорабатывать.

🔧 Установка:

1. Необходимо установить [Docker](https://docs.docker.com/get-started/get-docker/)

2. В данном модуле находится файл docker-compose.yml, после того как мы его добавили необходим перейти в папку и запустить его

```
cd 03-orchestration
docker compose up -d
```

3. Получения всех необходимых ключей API 

- Необходимо зайти в [Google AI Studio](https://aistudio.google.com/app/api-keys), войти в свой аккаунт и нажать создать ключ API
- Необходимо зайти в [Open AI](https://platform.openai.com/home) и сгенерировать также новый ключ. По идеи можно оставить тот же
- Необходимо зайти в [Tavily](https://app.tavily.com/home), зайти через гугл хром, выбрал бесплатный режим и получить в самом начале окна ключ

4. Конфигурация API Keys in Kestra

В начале нам необходимо отключить Kestra через `docker compose down`, затем все ключи, которые мы скопировали необходимо написать в терминале, где: 

```
export GEMINI_API_KEY="your-gemini-api-key-here" # required
export SECRET_GEMINI_API_KEY=$(echo -n $GEMINI_API_KEY | base64) # required
export SECRET_OPENAI_API_KEY=$(echo -n "your-openai-api-key-here" | base64)   # required for flow 3
export SECRET_TAVILY_API_KEY=$(echo -n "your-tavily-api-key-here" | base64)   # optional
```

Совет в начале в каком-нибудь .env это сделать а затем просто вставить в терминал и перезапустить через  `docker compose up -d`

Чтобы узнать ключи необходимо написать команду - `docker compose exec kestra env | grep SECRET`

А чтобы узнать ключи в самом приложении кестра необходимо зайти в localhost:8080 -> Tenant -> Secrets
