<summary>Что такое словарь в Python? / Как устроен ассоциативный массив?</summary>

Словарь в Python — это изменяемый, упорядоченный тип данных (порядок вставки сохраняется с Python 3.7), который хранит данные в виде пар «ключ → значение». Каждый ключ уникален, должен быть хешируемым и поддерживать сравнение через ==.

Словарь реализован через хеш-таблицу. Хеш-таблица — это структура памяти, где мы выделяем определённое пространство под записи. Когда мы обращаемся к ключу, мы берём его хеш, по хешу вычисляем номер ячейки в памяти и туда записываем значение. Если два ключа дают один и тот же индекс — это коллизия, тогда Python ищет следующую свободную ячейку и при поиске сравнивает ключи через ==. Когда таблица заполняется примерно на две трети, она расширяется, и элементы перераскладываются.

`Доп.вопрос`: Что может быть ключом в словаре?

Любой неизменяемый тип данных - int, float, bool, complex, строки, кортежи, bytes, none, frozenset (неизменяемое множество)

`Доп.вопрос`: Какая скорость у словаря при поиске, доступу к элементу, вставке или удаления элемента

При при поиске, доступу к элементу, вставке или удаления элемента: O(1), но если нам нужно прочитать из середины списка, то от O(N)

`Доп.вопрос`: Где быстрее поиск: в словарях или списках?

В словаре поиск по ключу быстрее — в среднем O(1), так как словарь реализован как хеш-таблица. В списке поиск значения занимает O(n).

```python
fruits = ["apple", "banana", "cherry", "date", "elderberry"]  # Список
prices = {"apple": 50, "banana": 30, "cherry": 120 } # Словарь
```

`Доп.вопрос`: Как получить список ключей из словаря?

Ответ: через list

```python
example = {
  'id': 7, 
  'name':'Shiba', 
  'color':'brown', 
  'speed':'very slow'
}

list(example)  # => ['id', 'name', 'color', 'speed']
```

`Доп.вопрос`: Как проверить, существует ли значение в списке?

Существует два способа - через `in`, который возвращает булевое значение и `index`, который возвращает индекс первого найденного значения, а если он не находит данное значение, то кидает исключения

```python
nums = [10, 20, 30, 40]

print(20 in nums)       # True
print(25 in nums)       # False
print(nums.index(30))   # 2
print(nums.index(99))   # ValueError: 99 is not in list
```

У нас есть инструкция - `del`, которая удаляет элемент по индексу. А также есть методы, которые работают со списком, например: `remove` - удаляет первое совпадение значения `pop` - удаляет элемент по индексу и возвращает его

```python
popped = lst.pop(1)
print(lst, "| вернул:", popped)
# ['вишня', 'дыня'] | вернул: банан
last = lst.pop()
print(lst, "| вернул:", last)
# ['вишня'] | вернул: дыня
```

<summary>В чем разница между list (списком) и tuple (кортежем)?</summary>

- Список изменяемый, кортеж нет. 
- У списка длина может увеличивать, а у кортежа нет. 
- Кортежи более производительны и занимают меньше памяти, чем списки, так как у списков под запасом еще хранится память
- Кортеж - хешируемый, список нет
- Список имеет большое кол-во методов для изменения, у кортежа всего 2 - это index и count для подсчета вхождений.

Я бы использовал список, если данные наши будут обновляться, а кортеж бы использовал для тех данных которые написали один раз и больше бы не использовали
</details>

Двойное равенство сравнивает значение объектов, а is сравнивает ссылки в памяти. Например можно проверить через id являются ли две переменные ссылками на один и тот же объект в памяти. 

```python
a = [1, 2, 3]
b = a

print(a == c)   # True  
print(a is b)   # True
print(a is c)   # False
```

<summary>В чем разница между append и extend?</summary>

- append(elem) - добавляет один элемент в конец списка. Элемент может быть как числом, так и список состоящий из нескольких элементов
- extend(iterable) - принимает 1 аргумент и он должен быть итерируемый - список, строка, кортеж и т.п. и добавляет по одному в конец
 
```python

example_01.append(3)        # [1, 2, 3]
example_02.append('str')    # [1, 2, 3, 'str']
example_01.append(3, 4)     # TypeError (принимает 1 значение)
example_01.append([4, 5])   # [1, 2, 3, [4, 5]]

example_02 = [1, 2]
example_02.extend('str')      # [1, 2, 's', 't', 'r']
example_02.extend(3)          # TypeError (не итер)
example_02.extend(3, 4, 5)    # TypeError (принимает 1 итер аргумент)
example_02.extend([3, 4, 5])  # [1, 2, 3, 4, 5] 
```

```python
s[3:]     # 'def'   — с 3 до конца
s[:]      # 'abcdef' — копия всей строки
s[::2]    # 'ace'   — каждый второй
s[::-1]   # 'fedcba' — разворот
```

<summary>Поддерживает ли Python регулярные выражения? Напишите регулярное выражение, которое будет принимать идентификатор электронной почты.</summary>

Да, поддержвается используя библиотеку (модуль точнее) re

```python
import re

email_regex = r'b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+.[A-Z|a-z]{2,}b'

def is_valid_email(email):
    if re.match(email_regex, email):
        return True
```

<summary>Что такое хвостовая рекурсия и почему нет оптимизации хвостовой рекурсии? Как это реализовать?</summary>

Хвостовая рекурсия — это когда функция вызывает саму себя в самом конце и сразу возвращает полученное значение, никак его не меняя. Возьмем в качестве примера число фибоначи -

```python
# Не хвостовая рекурсия - Компьютер не может сразу вернуть результат, 
# ему сначала нужно дождаться обоих вызовов и СЛОЖИТЬ их (+)
def fibonacci_bad(n):
  if n <= 1:
    return n
  return fibonacci_bad(n - 1) + fibonacci_bad(n - 2)

# Хвостовая рекурсия -  функция вызывает сама себя в самом конце 
# и сразу возвращает результат наружу без изменений
def fibonacci_tail(n, a = 0, b = 1):
  if n == 0:
    # Возвращаем накопленный результат
    return a
  return fibonacci_tail(n - 1, b, a + b)
```

В Python нет встроенной оптимизации хвостовых вызовов (TCO - Tail Call Optimization) по нескольким причинам: 

- Python не функциональный язык, и вместо хвост рекурсии он предлагает переписать на цикл, так как он проще, быстрее и в нем легче находить ошибки

- Во-вторых, оптимизация хвостовой рекурсии ломает трассировку стека: при ошибке было бы сложнее понять, как программа к ней пришла. 

Можно переписать хвостовую функцию через цикл или исп трамплин - функцию обертку, которая в цикле вызывает возвращаемые функции

- Обычный цикл for

```python
def fibonacci(n)
  cache = [0, 1]
  for n in range(2, n + 1):
    cache.append(cache[n - 1] + cache [n - 2])
  return cache[n]

print(fibonacci(8)) # 21 (1 ms)
```

- Трамплин
```python
def trampoline(f):
  def wrapped(*args, **kwargs):
    result = f(*args, **kwargs)
    while callable(result):
      result = result()
    return result
  return wrapped

@trampoline
def fibonacci_tail(n, a=0, b=1):
  if n == 0:
    return a
  return lambda: fibonacci_tail(n - 1, b, a + b)

print(fibonacci_tail(8))  # 21
```

<summary>Какие встроенные декораторы есть в Python?</summary>

Все они используется в работе с классами

`@property` — превращает метод класса в свойство. Позволяет обращаться к методу как к обычному полю (obj.value)
`@staticmethod` — делает метод статическим, он не получает ни экземпляр (self), ни класс (cls) в качестве первого аргумента. 
`@classmethod` - делает метод классовым. Первым аргументом он получает сам класс (cls), а не его экземпляр

```python
class Bank:
  def __init__(self, owner, balance=0):
    self.owner = owner
    self._balance = balance

  @property           # .._..
  def balance(self):
    return self._balance

  @balance.setter
  def balance(self, value):
    if value < 0:
        raise ValueError("Баланс не может быть отрицательным")
    self._balance = value


  @staticmethod     # .._..
  def is_valid_number(number):
    return len(str(number)) == 10 and str(number).isdigit()

  @classmethod     # .._..
  def from_dict(cls, data):
    return cls(data["owner"], data.get("balance", 0))

# -----------------------------------------------------------

acc = Bank.from_dict({"owner": "Аня", "balance": 100})  # @classmethod
print(Bank.is_valid_number(1234567890))  # True (# @staticmethod)
print(Bank.is_valid_number(123))         # False (# @staticmethod)
print(acc.balance)   # 100                (@property — обращаемся как к полю)
acc.balance = 200    # работает сеттер    (@property — обращаемся как к полю)
print(acc.balance)   # 200                (@property — обращаемся как к полю)
acc.balance = -50    # ValueError: Баланс не может быть отрицательным
```

<summary>Что такое итератор и генератор</summary>

Итератор - это объект который по одному выдает элементы из какой-то последовательности. И у него есть 2 метода - __iter__ - возвращает сам итератор, и __next__ для вывода элементов по очереди. Когда элементы заканчиваются он возвращает исключения StopIteration

```python
class Countdown:
  def __init__(self, start): self.current = start
  def __iter__(self): return self
  def __next__(self):
    if self.current <= 0:
      raise StopIteration
    value = self.current
    self.current -= 1
    return value


it = Countdown(3)

print(next(it))  # 3
print(next(it))  # 2
print(next(it))  # 1
# print(next(it))  # StopIteration
```


Генератор - особый вид итератора и создаётся c помощью функции def и yield. Он возвращает значения по одному, сохраняя своё состояние между вызовами next() и когда значения заканчиваются, он автоматически исключения StopIteration.

```python
def gen():
  yield 10
  yield "привет"
  yield [1, 2, 3]

g = gen()          # g — генератор
print(next(g))     # 10
print(next(g))     # привет
print(next(g))     # [1, 2, 3]
```

`Доп.вопрос`: Что такое yield

Yield возвращает значение, после чего сохраняет свое состояние и приостанавливает свое выполнение до след.вызова next(). В отличие от return, он не завершает функцию, а лишь ставит её на паузу.
</details>

метод send() - возобновляет выполнение генератора (как next()) и передаёт value где генератор был остановлен на yield
метод throw() - кидает ошибку, где генератор был остановлен, а сам генератор можно перехватить, обработать
метод close() - завершает генератор и выводит исключения GeneratorExit

```python

gen.send("привет")        # получил: привет
gen.throw(ValueError)     # это ошибка, пропускаю

```

<summary>Что такое MRO? Как это работает?</summary>
 
MRO (Method resolution order) — это порядок, в котором Python ищет атрибуты и методы у класса и его предков. Он строится для каждого класса с помощью C3-линеаризации. При множественном наследовании MRO определяет, какой метод или атрибут будет найден первым, если он есть в нескольких базовых классах.

Как работает: Сам класс -> родители слева направо -> их родители -> ... -> object

```python
class O: ...
class A(O) ...
class B(O) ...
class C(O) ...
class D(O) ...
class E(O) ...
class K1(A, B, C) ...
class K2(B, D) ...
class K3(C, D, E) ...
class Z(K1, K2, K3)

print(*[c.__name__ for c in Z.mro()], sep=' -> ')
# (Z -> K1 -> A -> K2 -> B -> K3 -> C -> D -> E -> O -> object)
```

<summary> Какие методы должны быть определены у типа, чтобы их можно было использовать как ключи /  Какие методы нужно реализовать чтобы наш класс был ключом в словаре?</summary>

Метод __hash__ для получения хеша по данному ключу и __eq__ нужен для сравнения объектов для избежаний (разрешение) коллизий (когда разные ключи дают одинаковый хеш)


```python
class Point:
  def __init__(self, x, y):
    self.x = x
    self.y = y

  def __eq__(self, other):
    if not isinstance(other, Point):
      return NotImplemented
    return (self.x, self.y) == (other.x, other.y)

  def __hash__(self):
    return hash((self.x, self.y))


d = {Point(1, 2): "a"}
print(d[Point(1, 2)])  # 'a'
```

<summary>Что такое дескрипторы? Есть ли разница между дескриптором и декоратором </summary>

Если декоратор работает с функцией, то дескриптор работает с атрибутами класса и при доступе к атрибутам он переопределяет его поведения. Например: `__get__` - для чтения атрибута, `__set__`  - для записи, `__delete__` - для удаление.

Например property, который может поддерживать чтение, запись и удаление атрибута.

```python
class Person:
  def __init__(self, name):
    self._name = name

  @property
  def name(self):
    print("property.__get__: читаем name")
    return self._name

  @name.setter # 
  def name(self, value):
    print("property.__set__: записываем name")
    self._name = value

  @name.deleter
  def name(self):
    print("property.__delete__: удаляем name")
    del self._name


p = Person("Alice")

print(p.name)      # сработает __get__
p.name = "Bob"     # сработает __set__
print(p.name)      # снова __get__
del p.name         # сработает __delete__
```

<summary>- Что такое метаклассы и в каких случаях их следует использовать?</summary>

Метаклассы — это классы, экземплярами которых являются другие классы.

По умолчанию это type. Они позволяют управлять созданием и поведением классов: добавлять или менять атрибуты и методы, влиять на создание экземпляров. 

```python
class Meta(type):
  def __new__(mcls, name, bases, namespace):
    # добавляем атрибут в пространство имён класса
    namespace["created_by"] = "Meta"
    return super().__new__(mcls, name, bases, namespace)


class A(metaclass = Meta):
  pass

print(A.created_by)        # Meta
print(type(A))             # <class '__main__.Meta'>
print(A().created_by)      # AttributeError — экземпляр не видит атрибут метакласса
```

<h3>Асинхронность, многопоточность и GIL</h3>

<details>
<summary>Чем отличается синхронный код от асинхронного</summary>

Если говорить про синхронный код, то он выполняется по очереди - строка за строкой и пока не будет выполнен предыдущий код, он не пойдет дальше.

А если говорить про асинхронный код, то благодаря eventloop и async await, мы можем переключаться между задачами `в одном потоке`. Например - повар может поставить на плиту чайник и пока он греется порезать овощи, приготовить посуду, наложить на стол. 

П.С. Конкурентность - Программа умеет работать с несколькими задачами одновременно (логически), даже на одном ядре процессора.

<details>
<summary>Основные преимущества асинхронности и как работать с асинхронностью.</summary>

- Он более быстрый чем синхронный код, так как можно выполнять другие задачи. 
- Он занимает меньше памяти чем поток  (thread)
- Достаточно удобный синтаксис и методы asyncio

Если говорить про то как работать с асинхронность, то нам необходимо написать async функцию и внутри указать await. Если несколько вызовов независимы друг от друга - мы можем создать 1 общий метод и собрать его через gather, чтобы они выполнялись параллельно
</details>

<details>
<summary>Что такое Coroutine (корутина), Future (фьючерс) и Task (задача)</summary>

Coroutine (корутина) - это функция объявленная через async def. Её вызов не выполняет тело функции сразу, а создаёт и возвращает объект-корутину. Для того, чтобы получить результат к этому объекту нам нужно выполнить await(). Пример [корутины](./backend/python/async/1.py)

Future (фьючерс) - это объект, где мы будем ожидать данные, которые у нас появится в будущем (результат выполнения ассинхронных операций в будущем). Пример [фючерс](./backend/python/async/futures.py)

Task —  это подкласс Future, который оборачивает корутину, планирует её выполнение в event loop и позволяет отслеживать состояние и результат этой корутины. Пример [task](./backend/python/async/task.py)
</details>

<details>
<summary>Что такое event loop (цикл событий)</summary>

Event loop — механизм конкурентного выполнения нескольких задач в одном потоке. Когда одна задача приостанавливается на await (например, ждёт ввода-вывода или таймер), event loop выполняет другую задачу, пока первая ждёт
</details>

<details>
<summary>В чем разница между IO-bound и CPU-bound задачами </summary>

Если IO-bound задачи - это задачи на ввод и вывод, то есть мы что-то отправили (API, база данных) - ждем и получаем ответ, то CPU-bound задачи - это больше про подсчет, а точнее про вычисление (сжатия и парсинг данных, обработка изображения, математика)

Для IO-bound мы используем asyncio, потоки, а для CPU-bound многопроцессорность и векторизация (NumPy).
</details>

<details>
<summary>Что такое асинхронность, многопоточность и многопроцессность </summary>

Ассинхронность - это когда мы работаем в рамках одного потока с несколькими задачами. При котором программа не ждет завершения долгой операции (например, ответа от сервера или загрузки файла), а переключается на другие дела, а к первой задаче возвращается, когда она будет готова.

Многопоточночность - это в рамках одного процесса создать несколько потоков распаларелить выполнения программы, но мы столкнемся с GIL который блокирует выполнения несколько потоков, если это не IO-Bound задачи

Многопроцессорность - одновременное выполнения задач, то есть один процесс - одна задача. И у каждого этого процесса есть своя память

</details>

<details>
<summary>Для каких задач взял бы многопоточность/ассинхронность</summary>

В большинстве случаев ассихнронность для IO-bound задач
</details>

<details>
<summary>Что такое GIL, как он работает и преимущество и недостатки его?</summary>

GIL (Global Interpreter Lock - Глобальная Блокировка Интерпретатора) -  основная задача в том, чтобы не давать интерпретатору питона работать больше одного потока за раз, если это не IO-bound задачи

Преимущество:

- Позволяет добавлять разные библиотеки на языке С / C++ - Numpy;
- GIL помогает легче управлять памятью - то есть у него есть подсчет ссылок. Если бы у нас было два потока, то рано или поздно это привело к различным ошибкам

К недостатком можно отнести, что многопоточность нельзя использовать по сути

Как обойти его? 

- В 3.11 - Субинтерпретатор внесли - это когда можно запустить несколько изолированных сред (интерпретаторов) в рамках одного процесса со своим ГИЛ
- В 3.13. - Завезли тестовую версию, которая полностью отключал GIL.
- Использовать ассинхронность для I/O-bound задач и использовать многопроцессорность для CPU-bound задач
</details>
